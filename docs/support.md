# Support matrix

The aim is one behaviour in every language: each implementation of Bead plays the same conformance files and is proven against the other in the interop. A difference stays on this page only until it closes.

Every cell is read from the tests. A cell that names a test file is supported, and that file, with the `describe` (TypeScript) or the test class or method (C#) named beside it, proves it. "Not tested" means no test holds it, whatever the code does; "not available" means the implementation has no such part. TypeScript test paths are under `implementations/typescript/src/`, C# test paths under `implementations/dotnet/tests/`. The sections of `spec/spec.md` say what each feature is; [the decisions](decisions/README.md) say why it is so.

## Interop

Each client is played against the other implementation's server of the interop service (`spec/interop-service.json`), over each transport both serve.

| Client     | Server     | Transport  | Cases | Test                                                                                                                                    |
| ---------- | ---------- | ---------- | ----: | --------------------------------------------------------------------------------------------------------------------------------------- |
| TypeScript | C#         | WebSocket  |    12 | `implementations/typescript/src/client/__tests__/interop.test.ts` (`the C# server of the interop service`, `over WebSocket`)            |
| TypeScript | C#         | HTTP/1.1   |    11 | the same file (`over HTTP`)                                                                                                             |
| C#         | TypeScript | WebSocket  |     9 | `implementations/dotnet/tests/Bead.Interop.Tests/InteropTests.cs` (`InteropTests`, each theory over `WebSocket`, and the transfer fact) |
| C#         | TypeScript | HTTP/1.1   |     8 | the same file (each theory over `HTTP`)                                                                                                 |
| either     | either     | HTTP/2     |     0 | not tested                                                                                                                              |
| either     | either     | Web Worker |     0 | not available (platform)                                                                                                                |

The cases are the same on both sides: a payload echoed, a string of the length asked, the application's own failure, an unknown procedure and service, an admission that refuses, a resolver that throws, a payload that is not JSON, a call cancelled by its signal and one past its timeout (each cancelled at the server too), a command the server asks, a paced subscription, a session opened and ended, and, over WebSocket alone, 3 MiB each way as transfers. The TypeScript side plays one case more, a subscription that is not paced, and counts more tests than cases, as it splits the echo from the bytes, and the refusals, into tests of their own where the C# side gathers them in theories.

The conversations and the transports' cases hold a server to them. A client's behaviour is held to the
other side by the interop alone, until the transports' file has a client part, by a decision of its own.

What no entry plays stays with each side's twin tests:

- a destination that is a router the relay calls through, with its two legs' limits and the session
  every requester shares behind it (spec 14.3 and 14.7): `router/server/__tests__/relay.test.ts` and
  `Bead.Core.Tests/RelayTests`, until a relay across languages comes with the federation of nodes;
- HTTP/2 and TLS, which both servers serve: open, as the transports' cases play HTTP/1.1 in clear;
- keep-alive, pipelining and a connection used again, which one socket per exchange leaves out;
- the transport's contract with its router, its events, its handles and its gauges, which each side's
  transport tests hold.
