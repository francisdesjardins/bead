# Support matrix

The aim is one behaviour in every language: each implementation of Bead plays the same conformance files and is proven against the other in the interop. A difference stays on this page only until it closes.

Every cell is read from the tests. A cell that names a test file is supported, and that file, with the `describe` (TypeScript) or the test class or method (C#) named beside it, proves it. "Not tested" means no test holds it, whatever the code does; "not available" means the implementation has no such part. TypeScript test paths are under `implementations/typescript/src/`, C# test paths under `implementations/dotnet/tests/`, but those written from the repository's root. The sections of `spec/spec.md` say what each feature is, and those of its companion `spec/debugging.md`, cited as "debugging §", what a side traces, filters and counts beside the wire, and those of `spec/transcoding.md`, cited as "transcoding §", what a side's gateway answers over HTTP; [the decisions](decisions/README.md) say why it is so.

## Leveled down

A leveling is no difference, since every side behaves alike: it is a place where Bead does less than a standard, or its own wire, allows, because one platform cannot do more and every side keeps to what it can ([0004](decisions/0004-one-behaviour-in-every-language.md)).
