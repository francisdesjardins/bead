# Support matrix

The aim is one behaviour in every language: each implementation of Bead plays the same conformance files and is proven against the other in the interop. A difference stays on this page only until it closes.

Every cell is read from the tests. A cell that names a test file is supported, and that file, with the `describe` (TypeScript) or the test class or method (C#) named beside it, proves it. "Not tested" means no test holds it, whatever the code does; "not available" means the implementation has no such part. TypeScript test paths are under `implementations/typescript/src/`, C# test paths under `implementations/dotnet/tests/`. The sections of `spec/spec.md` say what each feature is, and those of its companion `spec/debugging.md`, cited as "debugging §", what a side traces, filters and counts beside the wire; [the decisions](decisions/README.md) say why it is so.
