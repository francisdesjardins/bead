- **Status**: accepted
- **Scope**: every side's public surface: its names, `tools/names.tsv` and `tools/check-names.mjs`;
  the parameter rule, an options object, its required members and the conditional type; no tuple;

  `tools/check-surface.mjs`, `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt`, `bead-house`'s
  surfaces. Each language's rendering is
  [0007](0007-csharp-interfaces-blocks-two-parameters-no-warning.md)'s for the TypeScript and C#

## Context

Bead's surface is what an application and the code beadc generates call, and three languages mirror
it almost name for name, the TypeScript, C# and Rust sides alike: a name, a parameter or an export
that drifts on one side is a difference every reader of the others meets, and a break that lands on
one side and not on the others is two breaks for an application.

Each platform's own guidance pulls the sides apart where they meet. .NET's allows a named value
tuple, and the Rust API Guidelines' C-NO-OUT a tuple return, while a Rust tuple carries no names, so
a named C# tuple has no term-for-term rendering; C-NEWTYPE keeps a one-field newtype. An optional
parameter is a `?` on the TypeScript side, a default or an overload on the C# side, where CA1032 asks
an exception's constructors for one, and nothing on the Rust side, which has no optional parameter.
A default a library declares is exported by some platforms and kept internal by others, where Go's
`net/http` exports `DefaultMaxHeaderBytes` and Node's `events` its `defaultMaxListeners`, so an
application sets a value relative to it.

The options weighed, and not taken, as the rounds below state them: a required member as any member
a call cannot go without, unbounded, which lets a third essential thing in; a type per case for a
service's admissions on the C# side, which its overload and its generated record already serve;
rustdoc's JSON as the Rust side's list, which the pinned toolchain emits only under
`RUSTC_BOOTSTRAP=1`; the core's hidden `internal` as the road of a Rust transport's crate, and
serde's `__private` as its precedent; a named tuple, as .NET's guidance allows, and a tuple return,
as C-NO-OUT allows; an `…OrDelayResolver` union, the one `XOrY` name of the TypeScript surface; a
ratchet on tuples of two elements of one type, met by opening them into two parameters that swap as
easily; narrowing the whole family of declared defaults on every side, which would take some sixty
names from applications against the house's own form; an event of `(session, oldValue)`, which would
have each listener read half a change from the session; a JSON form that writes only a message of
its own types, which would level the C# side down; and the inline-object check in
`bead/options-last`, which reads syntax alone and would refuse the records of the call a side keeps
inside.

## Decision

**The surface is one.** A name on one side is the same name on every other, in its language's
case, and any language that can carry the protocol whole mirrors the surface almost name for name;
each language's own mapping of terms is its implementation's record, as
[0007](0007-csharp-interfaces-blocks-two-parameters-no-warning.md) is the C# side's, and
`tools/names.tsv` holds the mapping of the public names, one row a concept, each name with its kind,
which `tools/check-names.mjs` checks against each side's list; a name only one side holds and no row
explains is counted, and the count only falls.

**Every side takes two parameters, then one options object, and marks a required member in its own
form.** A function takes at most two parameters, then at most one options object, always last,
named `…Options`. Every member of it is optional, with the default its documentation states, but a
setting the object cannot be built without — where to connect, a server, an id — which every side
marks required: a member without `?` on the TypeScript side, a `required` member on the C# side, a
field the struct's constructor of its required members takes on the Rust side, the struct then
without `Default`. At most two members are required, and none is the operand the call works on,
which is a parameter; a third essential thing is a design to revisit. An options object with a
required member is a required parameter, and one without is optional: `?` or a default on the
TypeScript side, `TOptions? options = null` on the C# side, or an overload without it where a
platform rule asks for one, as CA1032 asks an exception's constructors; on the Rust side, which
has no optional parameter, `&…Options::default()`. **Where a member is required in some
instantiations alone** — a transport's connect options, a service's hooks — the TypeScript side
writes the parameter as a conditional type, required exactly where its instantiation has a required
member; the C# and Rust sides state it by an overload or a type of their own where their types name
the case, and otherwise take the member optional and refuse its absence where the object is used, a
difference the support matrix keeps as work to do. A command's options are a record of their own,
`CommandOptions`, on every side, its connection required, the request and notification makers and
the command resolver a client's router's, and the command maker and the request and notification
resolvers a server's, each refused on the other's as it is made, its side first; a client's and a
server's facades give their services typed by their side, with its makers alone:
`IServiceManagerClient` and `IServiceManagerServer`, `ServiceManagerClient` and
`ServiceManagerServer` on the Rust side. Options a side hands a callback are always given. An
options object with a required member stays an options object, not a request type. Each language's
rendering is its record's: [0007](0007-csharp-interfaces-blocks-two-parameters-no-warning.md) for
the TypeScript and C# sides, [0044](0044-rust-one-owner-per-router-traits-no-unsafe-two-parameters-no-warning.md) for
the Rust side.

**No tuple on the surface.** No public item takes or gives a tuple, on any side: no parameter,
return, member, type alias or constant holds one at any depth of its type, and no enum variant or
struct has two or more unnamed fields, a one-field newtype aside (C-NEWTYPE). What a caller
passes or reads is named. Two things are two parameters; a third essential thing is a record of
the call, named as every side names it — `RouterRequest`, `NotifyRequest` — or a type that holds
two of the things, or, on the TypeScript and C# sides, a call made in two, as a notification's
registration is there, which the Rust side makes one call of two parameters and the options;
several values given back are a record, which the Rust side makes `#[non_exhaustive]`, as
`TransportServerClient` is. Two tuples stay, since no caller builds them as a value of Bead's: a
parameter list's, every element labeled — a TypeScript rest's, an event map's, `Parameters<…>` —
and a map's entries in their platform's form, `Object.entries`'s pairs and a
`KeyValuePair<K, V>`, where the Rust side gives the map itself. The rule is stricter than .NET's
guidance, which allows a named value tuple, and than C-NO-OUT, which allows a tuple return: a
Rust tuple carries no names, so a named C# tuple has no term-for-term rendering, and a record can
grow where a tuple cannot. Inside a side, the count of
[0007](0007-csharp-interfaces-blocks-two-parameters-no-warning.md) and
[0044](0044-rust-one-owner-per-router-traits-no-unsafe-two-parameters-no-warning.md) binds every
function, a tuple counting as one parameter there and nowhere on the surface. A record of the
call is no options object: it holds the operand, which an options object never does.

A router's core, which both routers build on, is internal on every side: an application builds on
the routers, and stands behind a destination by a target it registers with a relay, a client router
or a connection of the relay's own (`RelayTarget` on the TypeScript side; `IRouterTarget`, which
`RouterClient` implements, or `ConnectionTarget` on the C# side)
([0010](0010-a-request-presents-a-credential-of-a-scheme.md), On what a procedure is handed of its
call's credentials).

**What one side exports, every side exports.** A side's public surface is what an application and
the code beadc generates call: the package's `exports` on the TypeScript side, the public types of
its assemblies on the C# side, the public items of each crate on the Rust side. A name public on
one side and internal on another is a difference, closed to the narrower form unless a decision
that meets the Tenth Man brings it to every side. **A default Bead declares is such a decision:
exported on every side**, as Go's `net/http` exports `DefaultMaxHeaderBytes` and Node's `events` its
`defaultMaxListeners`, so an application sets a value relative to it, in the house's form:
`LIMIT_DEFAULTS` on every side, `PACING_DEFAULTS`, `INTAKE_DEFAULTS` and the constants `HEARTBEAT`,
`CONNECT_TIMEOUT` and their kin on the TypeScript and Rust sides. A Rust default whose TypeScript
twin is a table's member takes that table, a `const` of the options struct the table satisfies —
`REQUEST_DEFAULTS`, `RECONNECT_DEFAULTS`, `METRICS_REGISTRY_DEFAULTS` — and one whose twins are
internal everywhere is internal. The C# side's twins of the family, and the TypeScript side's
defaults no other side exports, are additions that break nothing, work to do. **The envelope's
codec — reading and writing an envelope, its prefix, its header and a failure's record, the envelope
whole and the options of its reading — is internal on every side, as a router's core is.** An
application hands its transport's bytes to a router and reads a header where an event, a hook or a
result carries one, and those headers stay public. A side's own tests, fuzz targets, benches, tools
and interop service reach its inside as their platform lets: by path within the TypeScript package,
by `InternalsVisibleTo` on the C# side, and on the Rust side through one `#[doc(hidden)] pub mod
internal` of the core, outside SemVer as its documentation says and as cargo-semver-checks reads a
hidden item, for the workspace's members that are no library alone. A part of a side that needs the
core's inside and ships to applications — a transport — sits with the core: an assembly under
`InternalsVisibleTo` on the C# side, a feature of the core on the Rust side, as tokio keeps `net`.
Each side pins its surface, members included, to a list its gate holds
([0006](0006-a-rule-has-its-gate.md)), so the surface grows by a decision, never by accident.

A term renamed on one side is renamed on every side where it applies.

## Consequences

**A change of the surface lands on every side in one change**, its names, its parameters and its
exports alike, and, while the major is 0, it breaks in a minor
([0008](0008-three-version-axes-and-names-qualified-by-their-owner.md)): one break for an
application, never one a side.

**A third essential thing is a design to revisit**, never a third parameter, a tuple or a request
type: a record of the call, a type that holds two of the things, or, on the TypeScript and C# sides,
a call made in two.

**The gates hold it, as [0006](0006-a-rule-has-its-gate.md)'s table states them.** Across the
sides, `tools/check-names.mjs` holds each public name to its row of `tools/names.tsv`, and the count
of the names one side alone holds only falls. On the TypeScript side,
`implementations/typescript/tools/check-surface.mjs` pins the package's exports, each with its
declaration and its members, in `surface.txt`, judges each options parameter, refuses a tuple at any
depth and a parameter typed as an inline object that is not the options, each waiver listed with its
reason, beside oxlint's `bead/options-last`. On the C# side, `SurfaceTests` holds the options
records, the parameter count and the events, and PublicApiAnalyzers' RS0016 and RS0017 pin each
`src` project's `PublicAPI.Shipped.txt` and `PublicAPI.Unshipped.txt`, which
`tools/release.mjs prepare` brings up to date at a release. On the Rust side, `bead-house`'s
`surface`, `parameters`, `options` and `tuples` hold each library crate's items to its list in
`crates/bead-house/surfaces/`, the parameter rule, each options struct's shape and the tuples. On the
C# and Rust sides, the tuples of three elements or more a function takes are counted against a pin
that only falls.

**Review holds what no gate reads.** As 0006's list says, the parameter rule inside the C# side, its
count and what a third parameter may be; on the TypeScript side, what `bead/options-last` lets pass
in a function no entry exports and a callback aliased under a name ending in `Options`; and on every
side, a required member that is the call's operand. As `tools/check-names.mjs` says, a rename that
drops one name a side alone holds and adds another, keeping the count, is held by the review of its
file's diff alone.
