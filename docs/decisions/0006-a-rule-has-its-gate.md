# 0006 — A rule has its gate, or it is a preference

- **Status**: accepted
- **Scope**: the repository, and every implementation

## Context

This repository states many rules: about the wire, the conformance files, the interop, each
language's style, the lockfiles, the commits. A rule written in a README and nowhere else survives
exactly as long as the attention of whoever read it last, and every implementation multiplies the
places where that attention can lapse.

A gate is not free either. The worst failure a check has is finding nothing and reporting success: a
walk that reads no file, a filter that runs no test, an interop that skips.

## Decision

**Every rule names the thing that fails when it stops being true**, and that thing runs in CI, on
every push and every pull request, in one of its jobs, under `ci-ok`, which needs every other job so
that one check stands for them all. Each rule, and the job that holds it, whose comment in
[`ci.yml`](../../.github/workflows/ci.yml) says what it runs:

**A gate guards itself against finding nothing.** A floor says what it must have found: the comment
budget fails under 40 blocks in 10 files; Microsoft.Testing.Platform fails a run where no test ran,
with exit code 8, and Playwright one that found no test; `BEAD_INTEROP_REQUIRED=1` turns an interop
that would skip into one that fails, `BEAD_MQTT_REQUIRED=1` and `BEAD_AMQP_REQUIRED=1` a case over
MQTT 5 or AMQP 1.0 that would skip without a broker, `BEADC_PROTOC_REQUIRED=1` a builder test that
would skip without protoc, `BEADC_WRAPPERS_REQUIRED=1` a wrapper's test that would skip without
bash, PowerShell 7.6 or, on Windows, the right to make a symbolic link, and `BEADC_IMAGE_REQUIRED=1`
one that would skip without beadc's image; the TypeScript and C# sides' envelope fuzz tests fail
where `spec/vectors.json` gives them 100 seeds or fewer; `tools/check-versions.mjs` fails where no
`v*` is reached and where a released section of the CHANGELOG has no tag, and a document none of
whose files repeats its version; `spec/check.py` fails where a table of files has lost a row whose
counts it holds, or a row the words that state one, or the runner's floor the suite its row counts,
and on a number a row states that no count holds; the `beadc breaking` step compares against the
newest `vX.Y.Z` whose commit is not HEAD's, read by the tag's commit and never by ancestry, so a
release's own commit holds against the release before it, and fails where no such tag is found or it
carries no blueprint, and on every warning, a waiver that waived nothing among them; a branch behind
a release's merge-back merges `develop` first; protobuf's conformance suite fails a side, the Rust
side's testee as the others', whose successes and expected failures are not 5,601, or whose skips
are not 48, and its text-format suite's skips not 909, and a testee answers a binary request for a
message it lacks as a runtime error, never a skip, but the unstable edition's, which no stock
generator compiles. A floor is passed by a wide margin and fails only when code really went away,
which is worth being told.

**What comes from another's hands is held where it comes in.** An action runs by its commit's full
sha, its version in a comment beside it, since a tag moves and a moved tag runs another's code in
CI, as GitHub's security hardening guidance for Actions advises; a step fails any `uses:` pinned
otherwise. OSV-Scanner reads every lockfile against the advisories OSV knows, and NuGetAudit, at
`NuGetAuditMode` `all` and `NuGetAuditLevel` `low` in `Directory.Build.props`, every C# package
restored, direct or transitive, against those NuGet knows: a known advisory of any severity fails
the run, NuGet's as a warning the build makes an error. Semgrep runs its community rules for
TypeScript, C#, GitHub Actions and secrets, the generated folders and the goldens left out; its
rules are its registry's, fetched at each run, so a rule added there may fail a commit that changed
nothing, which is read as a finding, never as a flake, as `ci.yml` warns where the step stands.
Each scanner runs from its image at its digest, as shellcheck does, so a scanner changes by a change
of its pin. CodeQL is not taken: its code scanning, on a private repository, needs GitHub Advanced
Security.

**Coverage holds a floor of another kind, set close by design: a ratchet.** What each side's tests
run is held to the side's floor in [`tools/coverage-floors.json`](../../tools/coverage-floors.json),
on each measure it names, lines and branches, or lines and regions on the Rust side, which
`tools/coverage-report.mjs` compares unrounded; a floor fails where nothing was measured, and on a
measure no report measured. A floor sits half a point under what was measured, so an async path that
a run may or may not take fails no push; `--raise` moves it up to what a run measured, less that
half point, at a release or whenever the tests gain, never down, and a floor lowered is a decision,
with its reason. The sides' floors differ, a measure of each side's code and not a behaviour, so no
row of `docs/support.md` holds them.

**A ceiling is a policy, and is chosen as one.** The comment budget's, 50 words to a comment and 120
to an internal JSDoc, is a decision about what a reader's attention is worth, never a snapshot of
what the code weighs at one moment.

## Consequences

**Adding a rule means adding what fails**, or writing it as a preference. A rule that grows a gate
leaves the review's list for the table above.

**A gate that reads the artifact is the kind to prefer**: the conformance files, the regenerated
bytes, the built assemblies with their warnings. A count can be satisfied by editing a number; a
vector cannot.

**Gates owed**, the one list a gate's landing edits, moving its rule to the table above:

- a report of the vectors and conversations each side's tests play, where `spec/check.py` sees the
  groups and files they name ([0004](0004-one-behaviour-in-every-language.md));
- a check that every file of entries but the vectors, which their groups name, is named by a line
  of its document, and that the line's label is its file's, as the companion's are
  ([0004](0004-one-behaviour-in-every-language.md));
- a check of the C# side's parameters, which no analyzer of .NET's recommended set counts
  ([0007](0007-csharp-interfaces-blocks-two-parameters-no-warning.md));
- tests for `tools/check-commits.mjs` and `tools/check-links.mjs`, among the root's tools' tests,
  which the `commits` job runs.

**The hooks copy two gates and add a clone's own.** `.githooks/commit-msg` holds a subject to
Conventional Commits before git records it, as CI's `commits` job does, and `.githooks/pre-commit`
the staged root files to their format, as its `typescript` job does, when the TypeScript side is
installed; both hooks run the checks a clone keeps for itself, which CI cannot run. A clone opts in
with `git config core.hooksPath .githooks`.
