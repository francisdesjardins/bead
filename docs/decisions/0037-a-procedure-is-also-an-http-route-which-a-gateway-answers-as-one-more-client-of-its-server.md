## Context

**A page, curl or a generator that speaks HTTP and JSON reaches no Bead procedure.** The ecosystem's
norm for answering one is gRPC transcoding, `google/api/http.proto`
([googleapis](https://github.com/googleapis/googleapis/blob/14a161a98ef045be80c12ab69d924504a756f109/google/api/http.proto),
Apache-2.0), which grpc-gateway, Envoy's `grpc_json_transcoder`, Google's APIs and Cloud Endpoints
read: an `HttpRule` of `get`, `put`, `post`, `delete`, `patch` or `custom`, a path template of
literals, `*`, `**` and variables, a `body` and a `response_body`, `additional_bindings`, every
field the path and the body leave read from the query. [AIP-127](https://google.aip.dev/127) and
[AIP-134](https://google.aip.dev/134) say how an API uses it, `update_mask` among it. The Connect
protocol answers every procedure at `POST /<package.Service>/<Method>`, and `GET` there for one
marked `idempotency_level = NO_SIDE_EFFECTS`; Vanguard, its REST transcoder, routes by a trie that
tries a literal before `*`, then `**`, and maps a `get` rule with no condition. About thirty `get`
rules in eight googleapis protos carry no `idempotency_level`.

**What a gateway that is one more client binds to a connection is every caller's**: a connection's
session, one subscription per procedure and session, its answering calls, its transfers, the address
a refusal tells. One connection for every HTTP caller lends the first caller's session to the next,
a deputy's confusion ([CWE-441](https://cwe.mitre.org/data/definitions/441.html)); a pool keyed by
credential gives every caller presenting none one key.

**The two stock libraries part on protobuf's JSON mapping**, probed on `@bufbuild/protobuf` 2.16.0,
the TypeScript side's pin, and Google.Protobuf 3.36.2, the C# side's, each through binary as a call
goes; [protobuf's conformance suite](https://github.com/protocolbuffers/protobuf/blob/v36.2/conformance/binary_json_conformance_suite.cc)
at v36.2 holds a library to the mapping where it has a test. Where they part, and the rule of

Some of these no rule around a library can close: the value a resolver receives differs (D25), the
name a writer picks differs (D21), one side answers where the other fails (D23), and the C#
library's text costs two parses and a rewrite in, a reparse out (D27). protobuf's own Python
library, upb's, parts from both and from the suite on other edges besides: it reads a double's
string as Python's `float()` does, `"inf"` and `" 1"` among them, and refuses the largest `float`
it writes itself.

**What the standards say of the rest.** [RFC 9457](https://www.rfc-editor.org/rfc/rfc9457) states a
problem's `type`, `title`, `status` and `detail`, and its own example carries a request's errors with
a JSON Pointer of RFC 6901's fragment form. The WHATWG's
[Server-Sent Events](https://html.spec.whatwg.org/multipage/server-sent-events.html) have an
`EventSource` reestablish its connection whenever a 200 stream's body ends, send `Last-Event-ID`
when an event wrote an `id`, stop on any other status, 204 named for that, and dispatch an event
with no name as `message`; it writes no header of its page's. The Fetch Standard shows a page's
`Origin` on every request but a `GET` or a `HEAD` that is no CORS request, and Fetch Metadata's
resource isolation policy refuses a request from another site but a navigation, which OWASP's CSRF
cheat sheet names as defense in depth. OpenAPI 3.1.1's base dialect only annotates `format` and
`contentEncoding`: probed with the builder's ajv, a schema of `Everything` takes `{"at":"nope"}`, a
tenth fraction digit, year 0000 and a 20-digit `int64`, each of which both libraries refuse.

The options weighed:

- **One connection for the gateway**, every caller's: its sessions, subscriptions and bounds lent
  across callers. **A pool keyed by credential**: every caller presenting none shares one key, and a
  token renewed splits one caller in two.
- **A server of the gateway's own** over an in-memory transport: two offers of each service, two
  session managers, a notification reaching one; refused for the join of
  [0036](0036-an-in-memory-transport-joins-two-routers-of-one-process-and-a-server-takes-several-transports-through-one.md).
  **The gateway mounted on the HTTP transport's listener**: no router gained, a transport coupled to
  a gateway.
- **`GET` for a procedure marked `NO_SIDE_EFFECTS` alone, a `get` rule refused otherwise**: every
  `get` rule of googleapis refused, where the gate holds what a `GET` lets through.
- **Two routes one path matches refused**: `google.longrunning.Operations` refused, where the peers
  answer by precedence.
- **A sandwich of rules around each stock library's JSON**: ten of the rows closed, D15 to D27's
  not, and the C# side's cost.
- **A status by the code alone**: a gateway that is a requester raises some codes of its server's
  answer, which its caller cannot mend.
- **An unpaced stream**: every notification sent, a reader that stops reading holding the gateway's
  memory or dropped with no word. **An `EventSource` let to reconnect**: a `CAPACITY_EXCEEDED`'s gap
  hidden behind a new call.
- **A section 19 of `spec.md`**: a gateway's statuses moving the wire's version, where a side may
  offer none.
- **JSON for every body**, a `text` and a `raw` one in a string: one type, every `POST` preflighted,
  a third larger, never streamed.
- **OpenAPI 3.2.0**, whose `itemSchema` describes a stream: a generator that reads 3.1 alone
  refusing the document.
- **The blueprint's growing objects opened**, JOSE's whole rule: a typo in a hand-written blueprint
  passing unseen.

## Decision

**A gateway is beside the wire, one more client of its server** (transcoding 1, 2). In process, its
calls cross an in-memory transport into the application's own server, which takes them beside its
other transports through a joined transport, one router, one admission, one session manager, each
service offered once
([0036](0036-an-in-memory-transport-joins-two-routers-of-one-process-and-a-server-takes-several-transports-through-one.md)).
It answers on a listener of its own or as a handler an application mounts, never on the HTTP
transport's, and both take one policy object of hosts, origins, proxies and bounds, so two lists
are never kept alike in silence; one origin for `/bead` and `/api/…` comes from a proxy in front.

- **One Bead connection per HTTP exchange** (transcoding 2.1), drawn as its request passes the
  gates, closed as its response ends: everything `spec.md` binds to a connection is one caller's. A
  connection's session that a call opens is the gateway's, and ends with its exchange; a command to
  its connection is answered `SERVICE_UNKNOWN`, its client declaring no resolver (2.5, 2.6).
- **The credential** (2.4): the `authorization` field whole, presented `ELSEWHERE` beside the
  request, as `POST /bead` carries one; by the gateway's option `bearer-jwt`, a `Bearer` token
  presented as a `JWT`. Never `OPAQUE`; no cookie, no query.
- **Routes** (3): `POST <prefix>/<Service>/<procedure>` always, `/api` the prefix by default, and
  `GET` there for a procedure marked `NO_SIDE_EFFECTS`, Connect's rule for its own form; each
  `google.api.http` rule served as written, a `get` rule its author's word that its method reads,
  `custom` refused. A path is read raw, a dot segment matching nothing; its verb splits at the last
  unencoded `:` of its last segment; where two routes of one method match, a literal before `*`,
  `*` before `**`, a template that ends where the path ends before a `**` of none, the order
  Vanguard's trie walks, stated whole so no two sides part on it. The builder refuses only a tie,
  and a gateway refuses a table that holds one as it is built, since two tables built apart may join.
- **Binding** (4): `http.proto`'s rules alone, every value made the JSON the mapping reads, the query
  read as the WHATWG URL Standard's `application/x-www-form-urlencoded`, `+` a space; a `PATCH`'s
  absent `update_mask` filled from the keys its body holds, as grpc-gateway's `allow_patch_feature`
  fills one, so a caller clears a field by sending it.
- **The JSON form is Bead's own mapping** (5), one reader and one writer a runtime, over its
  descriptors and its library's reflection, the binary payload still its stock library's alone, as
  [0031](0031-a-proto-payload-is-protobufs-format-and-bead-states-only-its-own.md) has every `proto`
  payload go: what Bead writes is the JSON side of a message its library holds, never a byte of the
  wire. Every row of the table above is a rule of 5.2 to 5.7, and where the mapping's text is silent
  the rule is the suite's expectation, then the text, then the reading that refuses the most (5.5).
  The suite's `Int32FieldQuotedExponentialValue` makes a 32-bit integer's string any JSON number of
  an integer's value, `"1e5"` among them, where a 64-bit one's is decimal alone, D8's rule; its
  `AnyEmpty` has an `Any` of an `Empty` carry no `value`. Bead's proto JSON form writes 17.7's
  tokens, a message's members by field number, a field's number being its own for life, a map's
  entries sorted, `@type` first, a `float` at its shortest, written as Number::toString writes those
  digits, and nesting by 17.9.3's count, so a result reads in a browser's network tab in its
  `.proto`'s order and one result is one sequence of bytes on every side.
- **Failures** (7): `application/problem+json`, its members in 17.7's canonical form; a protocol
  code's `type` `tag:francisdesjardins.ca,2026:bead/<NAME>`, absolute and resolving nothing, as RFC
  9457 §3.1.1 allows, so no deployment is tied to a host; an application failure's under the problem
  types its definitions give, `about:blank` with RFC 9110's phrase otherwise. A status by where its
  code arose: the caller's 400, 413, 422; the server's answer the gateway could not take, and a
  `proto` request its server could not read, 502; the gateway's own configuration, a scheme its
  server takes none of, 500. An application failure is 400, its identity in `type`, `title` and
  `code`; its own status waits for the options' v1 freeze. `PAYLOAD_INVALID` is 422, its violations
  in `errors`, each pointing at its field by JSON names.
- **Notifications as Server-Sent Events** (8), chosen by `accept: text/event-stream` alone: the
  result, then each notification as a plain `message` event, then the failure that ends them, each
  event an `id`; a request carrying `Last-Event-ID` answered 204 and no call, so an `EventSource`
  stops and its page is told rather than called again behind the gap; paced by the response's drain,
  a subscription `PACED` within a window of 16, so a reader that falls behind holds its server's
  queue, where [0002](0002-a-subscription-goes-at-its-clients-pace.md)'s keys and bound tell it, never
  the gateway's memory.
- **The gates** (10) are the HTTP transport's, in 15.6's order, with Fetch Metadata's step: a
  request with no `origin` from another site refused but a navigation to `/openapi.json`, a default
  route's `GET`, or a `get` rule on a marked method. Calls and streams are bounded apart, calls by
  `maximumExchanges` and `maximumExchangesPerAddress`, 10,000 and 256, since one lives a request,
  streams by 15.12's connections' bounds, 64 an address, since one lives as long as its reader.
- **The document** (11): OpenAPI 3.1.1, one a blueprint, written once by the builder in the
  blueprint's own form and embedded byte for byte in an output with `http: true`, served at
  `/openapi.json`; each schema the one form Bead writes, a `pattern` beside each `format` the base
  dialect only annotates, and what no schema carries said in its description. The blueprint's
  routes and messages' shapes are members under no feature, `requires` kept for what a target must
  play
  ([0022](0022-a-proto-becomes-one-checked-blueprint-and-each-language-is-generated-from-it.md)).
- **Where it is stated**: a companion, `spec/transcoding.md`, on the spec's axis under a version of
  its own, its file repeating `transcodingVersion`, tagged `transcoding-v`
  ([0008](0008-three-version-axes-and-names-qualified-by-their-owner.md)): a gateway is beside the
  wire, a side may offer none, and a status moved need not move the wire's version.

## Consequences

**A connection costs a router client and a handle per HTTP exchange**, which each side's bench
measures as `exchange.*`, a connection drawn, called once and closed
([Measurement](../../README.md#measurement)), so a regression shows; a connection opened and closed
in the trace and the connections' gauge for each exchange, which is what HTTP is.

**Some of the wire's reach does not cross a gateway**, each a row of the support matrix's "Leveled
down": a command over a gateway (`SERVICE_UNKNOWN`); a connection's session (it ends with its
exchange); a stream's resume (a reconnection is answered 204); a stream's window (its reader's pace
is its socket's); a `custom` rule; a `**` variable in the document (one parameter); what no schema
carries; and, under 3.1.1, a stream's items, which 3.2.0 describes by `itemSchema`.

**The route is no guard**: a procedure is reached by its default route whatever rules map it, so a
proxy's rule on a rule's path guards nothing; the guard is its admission, which every route meets
alike. A page of another origin preflights each route's URL once per `max-age`, a browser keying its
preflight cache by URL, where `POST /bead` has one URL
([0027](0027-an-http-server-answers-cors-to-the-origins-it-names-and-to-no-other.md)).

**The mapping is Bead's to keep**: its third implementation is the generator's, and protobuf's
conformance suite's JSON tests then hold the code that answers, each side's `failing.txt` naming,
with its reason, what Bead's rules part from it on, the same lines on both sides. Its cost against
each stock library's JSON is a benchmark of each side, so a regression shows.

**What comes next, each a round of its own**: a report's context, the exchange and the route it came
of; an event for each refusal of the gateway's own; and an occurrence's id in a problem, RFC 9457
§3.1.5's `instance`. Each adds surface on both sides, and none is needed for a problem to say what
failed and where.

**Its gates** ([0006](0006-a-rule-has-its-gate.md)): `spec/transcoding.json`, which both sides play
whole — its templates and bindings through their routes, its readings and writings through their
mapping, its failures through their problems, its events through their streams, and its exchanges
through their gateway over a real socket; protobuf's conformance suite's JSON tests through each
side's mapping; `tools/check-transcoding.mjs`, which holds each side's generated route table and
embedded document to what beadc writes; beadc's tests, which hold every document to OpenAPI 3.1's
schema and every body Bead writes to the document; and the generator itself, which runs protobuf's
Python library beside its own reading and writing and fails on any parting its entries do not name.
`spec/check.py` holds the companion's units as it holds the spec's, its ledger
`spec/transcoding-units.txt`.

## The Tenth Man

The decision met the Tenth Man ([0009](0009-conventional-commits-git-flow-and-the-tenth-man.md)) at
xhigh effort, in one round. It met nine objections, each claim checked against the code, the texts
it cites and the probes before it was answered: eight accepted, one in part, none refused. The
objection on the in-memory connection is kept in
[0036](0036-an-in-memory-transport-joins-two-routers-of-one-process-and-a-server-takes-several-transports-through-one.md),

with, met five more: three accepted, one in part, one refused. A second round, on what a gateway's
problems carry and what it reports, met ten more: seven accepted, one settled on the transport's
rule, one held ahead, one refused; the coverage work on both sides found nine more, each settled;
